# SiteComms Australia — Agent-Ready Foundation change log

Date: 19 September 2026. Baseline: complete Phase 1 ZIP, 120 files. Scope: an implemented shared-core foundation, **not** a tested external-client pilot or production deployment. No funding/finance research or pricing re-calibration was performed.

## Implemented

**Shared pricing capability.** Added typed result/status/scope contracts, strict configuration validation, explicit input certainty and model defaults, source/rule versions, public source projections and source-failure policy. Wrapped the existing calculator rather than rewriting it. Unknown fields/counts and corrupt saved links no longer silently become valid assumptions. Empty sites return clarification; larger systems retain numbers but require design review; quotes and unimplemented decisions cannot be inferred.

**Human parity.** The existing calculator, editorial presets, school price bands and care example now use the shared assessment. The result and browser PDF consume its summary, limitations, provenance and defaults. Enquiry context is inspectable before submission and caller-supplied values are labelled unverified in the received email. No new enquiry tool is exposed.

**Useful public content access.** Moved the existing 12-guide directory to one record set, used by the ordinary guide page and a small deterministic keyword-search capability. Added a normal human filter without hiding links behind chat. Derived provenance from the existing school comparison source register without claiming fresh manufacturer/availability verification.

**Controlled integration seam.** Added two thin server-to-server HTTP routes over the same handlers, disabled by default. A strong server-only key, strict body/query limits, safe errors, no-store responses, optional redacted events and a local abuse backstop are present. Real hosting/proxy/abuse controls still need staging verification. This is **not MCP, WebMCP or a publicly enabled agent connection**.

**Documentation and tests.** Added site profile/source map, contracts, lifecycle/rollback instructions, owner decision list, supplied master standard, 70 captured pricing fixtures, boundary/source/parity/API tests, integration-status page and a sanitised environment template. `package.json` changes only add test scripts; dependency versions and lockfile are unchanged.

## Intentional behaviour change: automatic assessment logging retired

The prior result-view effect silently sent complete calculated results to a storage/PDF endpoint. It is removed. `POST /api/pricing-tool/output-log` now returns 410 without writing data. Downloaded PDFs are still generated by the browser; reviewed human enquiries still use the existing form. **Historical Supabase tables, objects and records have not been changed or deleted.** Check any downstream reporting that expected that automatic stream. Restoring durable assessment storage requires a separate purpose/retention/authorisation/idempotency review, not restoration of the blind writer.

## Preserved

Original visual assets, global stylesheet, pricing configuration, arithmetic engine, package lockfile, framework/dependency declarations, preview/noindex controls, genuine operator contact and existing core URLs are retained. There is no design-system replacement, new LLM dependency, vector database, new data store, state pricing multiplier or provider forwarding.

## Evidence and limits

Read `docs/agent-ready/VALIDATION.md` for exact executed tests and unavailable checks. Core/source/route-function tests are not a full Next production build, visual browser audit, rendered PDF test, live email test, protocol-client validation or organic-discovery result. This environment could not install dependencies because of registry DNS failures. The hosting agent must complete the normal build/preview gate before a deployment decision.

## Next

Review/integrate this foundation on the hosting agent's preview. Then undertake state-specific funding research, followed by finance research, and add only supported data/rules to the shared core. Select and actually test an external client before adding a protocol adapter or claiming agent compatibility.
